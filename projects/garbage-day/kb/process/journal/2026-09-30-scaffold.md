## Surprises and what they changed

- **Online, the rival's power-ups were invisible.** The local game draws both players' effects
  because it simulates both. An online client simulates only its own player, so the rival's
  Bomb, Shield and Fog landed nowhere on screen. The rival's view now lands them by the same rule
  ([`GD-STORY-012`](../backlog/GD-STORY-012.md)).
- **Checking the fight needed a real second player.** Scripted key presses can't clear lines or
  bank gems, and taps inside one frame count as one. The engine's Bot, bundled with esbuild and run
  from Node as a second client over a real socket, gave the browser a real opponent. It is what
  [`GD-STORY-015`](../backlog/GD-STORY-015.md)'s Web Worker will do in the app.

- **A failing check nobody here could read.** CodeQL's alerts show only on the Security tab, and
  no tool in an agent session reaches it or a check's annotations. The job's log lists the
  queries, not what they found. The workflow now keeps the SARIF as a run artifact, which the
  Actions API serves ([`GD-TICKET-030`](../backlog/GD-TICKET-030.md)).
- **The alert was wrong about bias and right about the seed.** CodeQL objected to arithmetic
  on a crypto-random number, the mulberry32 seed. Seeding a generator isn't drawing a biased
  number, but a 32-bit seed can be found from three bags, which shows every piece to come.
  Dealing from 128 bits fixed both.
- **A short drop lost garbage for good.** The referee resent unacknowledged garbage only to a
  player it had noticed gone. A connection down for under its 5 s of silence lost whatever was
  routed meanwhile. Every rejoin now resends.
- **A returning player played through the other's countdown.** Back from a lost connection or a
  closed tab, a player never heard `paused`, so the `resume` that followed didn't freeze them.
  The interruptions golden replay had recorded the head start. `resume` now freezes until its
  tick, and the replay was regenerated in its own commit.
- **A pause would have hibernated the referee away.** The Match DO kept its referee in memory,
  and woke only for messages. In a pause nobody sends any (pings are answered without waking
  it), so after about 10 s it could hibernate and lose the match. A 1-second clock while the
  match runs keeps it, and notices silence when no one sends anything.

- **"Latest" and "a day old" collide on release day.** Wrangler 4.144.0 and
  `@cloudflare/vite-plugin` 1.62.2 were published at 21:12 and 21:22 UTC the evening before, and
  `@cloudflare/workers-types` 5.20260930.1 at 01:29 UTC, all under the workspace's
  `minimumReleaseAge` of 1440 minutes. They are not needed until the app shell, so they wait for
  [`GD-TICKET-011`](../backlog/GD-TICKET-011.md). Stack and CI now defines "latest" as the newest
  release at least a day old.
- **`@vitejs/plugin-react` 6 no longer runs Babel.** The React Compiler goes through
  `@rolldown/plugin-babel` (0.2.4) with `@babel/core` 8.0.6 and the plugin's
  `reactCompilerPreset()`. The native oxc route exists but is marked experimental.
- **ESLint's project service needs every linted file inside a tsconfig.** The first lint failed
  with "vitest.config.ts was not found by the project service"; a root `tsconfig.json` that holds
  only the root Vitest config fixed it, and the typecheck now includes it.
- **Knip flagged `react`, `react-dom` and `@types/react` in `ui`** as unused development
  dependencies, although the tests need them; it also reported the entry patterns first written
  in `knip.json` as redundant. `knip.json` is now two lines of ignores.
- **No project references.** Packages export their TypeScript source, so `tsc -b` (which needs
  every package to emit) gave way to `tsc --noEmit -p` per package.
- **The design's path-filtered workflow would have blocked the rest of the repo.** It listed
  eight required checks from a workflow that runs only when the project changes. GitHub waits
  forever for a required check that never starts, so every pull request for another project
  would have hung once the owner marked them required. Pull requests now always start the
  workflow, a `changes` job skips the work when the project is untouched, and one summary check
  is required.
- **A pull request already existed.** The owner had opened #10 from this branch, so the
  acceptance criterion "a pull request shows every job green" was met there, and dependency
  review ran for real instead of being skipped.
- **The proof of concept had a bug and a spec mismatch.** A Bomb landing during the 0.2 s clear
  delay moved the board but not the rows waiting to clear, so the wrong rows cleared; the port
  fixes it. Sudden death stopped at level 15, where the game rules say 20; the port follows the
  rules. Both are in `GD-TICKET-008`'s Resolution; neither needed a new item.
- **The spec uses the name it rules out.** The PRD says the game never uses the Tetris name, but
  the game rules, UI language, controls page and PRD stats call a four-row clear a Tetris. The
  engine now reports clears as data, and choosing the word is
  [`GD-TICKET-018`](../backlog/GD-TICKET-018.md), for the owner (default "Quad").
- **Five of my own test expectations were wrong**, not the engine: two T-spin boards with the
  wrong corners, a wall-kick board that blocked the kick it meant to test, a four-line clear that
  was really a perfect clear, and a gravity count that forgot the spawn tick. Hand-checking and
  the first run caught them.
- **The proof of concept relayed boards during a pause.** The architecture says the referee stops
  relaying while paused, which the proof of concept never did; the port does, and re-sends the
  last locks on resume. Recorded in `GD-TICKET-009`'s Resolution.
- **M1's exit criterion had an uncarried half.** "Identical in Node and the browser" was in no
  item; `009` covers Node. Chromium shares Node's V8, so the real check is Firefox and WebKit:
  [`GD-TICKET-019`](../backlog/GD-TICKET-019.md).
- **Every referee test passed on its first run**, which is suspicious for 24 new tests. Their
  expectations came from the rules text, not from the code's output, and the interruptions
  replay's timeline, read event by event, matched the rules too.
- **Run-length encoding alone can't meet the protocol's 200-byte goal.** A varied full board is
  all runs of one, which run-length makes longer, not shorter. The encoding sends whichever is
  shorter of runs and 4-bit packing; the packed form is at most 161 bytes.
- **The compile-time agreement check caught a real mismatch at once:** the engine's bag is a
  readonly array and Zod infers a mutable one. The check started as exported functions; Knip
  flagged them as unused, so it became `expectTypeOf` assertions in the tests.
- **The designed preview could never have worked.** Cloudflare makes no version URL for a Worker
  with Durable Objects, so `wrangler versions upload` gives no preview. Worker Previews (open
  beta since 2026-09-22, `wrangler preview`) give each pull request its own URL and its own
  Durable Object storage, which is better than the design anyway.
- **The scaffold's install-script allowlist was never read.** pnpm 11 renamed
  `onlyBuiltDependencies` to `allowBuilds` and ignores the old name. pnpm 12 blocks unapproved
  scripts by default, so nothing ran unapproved, but the config and the docs claimed a setting
  that did nothing. Found when the first packages with install scripts (esbuild, workerd) came
  in.
- **The Workers test pool was renamed.** `@cloudflare/vitest-pool-workers` stopped at 0.22.0 in
  August, and its runtime rejected the compatibility date ("newest date supported … is
  2026-08-22"). Its successor is `@cloudflare/vitest-plugin`; the Vitest exception now names it.
- **Wrangler brought ten `undici` advisories** (two high, local tooling only). They are overridden
  to upstream's own fix, 7.29.1, until the Wrangler release that pins it is a day old.
- **React 19's `use()` needs an async `act` in tests.** The suspended status line didn't
  re-render within `findByText`'s window until the render and the promise were awaited inside
  `act`.
- **The first browser-test push broke the Worker tests in CI.** Declaring
  `@vitest/browser-playwright` in the engine package made pnpm build a second Vitest, and the
  Workers test plugin met the other one. I hadn't rerun `pnpm test:worker` locally after that
  change; moving the packages to the root fixed it. The same push showed the golden replays
  passing in Chromium, Firefox and WebKit.
- **`pkill -f` killed my own shell twice**, because the pattern was in the command line. The
  screenshot script now stops the server by PID.
- **The proof of concept loads awkwardly from TypeScript tests.** The project's
  `"type": "module"` makes Node read `live-engine.js` as a module with no exports, so the parity
  test evaluated its source instead.
- **`pnpm/action-setup` points to a newer `pnpm/setup`**, which installs pnpm and Node in one
  step. Kept `pnpm/action-setup` 6.1.0 with `actions/setup-node` 7.0.0, the pair its README still
  supports for pnpm 12, rather than adopting a v1 action in the first CI run.
- **A new Cloudflare account can't deploy a Worker until it has a `workers.dev` subdomain.** The
  first `wrangler preview` got as far as
  `/accounts/***/workers/workers/garbage-day/previews/…/deployments` and stopped with "You need a
  workers.dev subdomain in order to proceed … Opening the Workers landing page for the first time
  will create a workers.dev subdomain automatically. [code: 10063]". So the token, the account
  ID and the job are right. The fix is one visit to Workers & Pages in the dashboard, and no
  change to the workflow.
- **`wrangler preview --json` isn't only JSON.** With the subdomain in place, the preview deployed,
  but `jq` failed with "Invalid numeric literal at line 1, column 6". Wrangler prints its
  progress lines (`Using redirected Wrangler configuration.`, the asset upload) to stdout ahead of
  the JSON document. The job now parses from the line that opens it. Feeding the logged output
  through the old and new commands reproduced the error and then the URL.
- **A green deploy job and a loading page were not a working preview.** The owner's screenshot
  showed "Server unreachable": Cloudflare's Previews configuration page says "Previews do not
  inherit production settings", and that covers Durable Object bindings. The job log had shown it
  all along: the deployment's `env` listed only `ASSETS` and `ENVIRONMENT`. The health check in
  the page is what caught it, which is what it was built for.
- **A required check depended on the Ubuntu mirror.** `test-browser` passed in minutes all day,
  then was cancelled twice at once, with the tests never started. `--with-deps` had been fetching
  a few hundred megabytes of apt packages every run. Nothing in the pull request had changed;
  what changed was the mirror's speed. Playwright's container image removes the dependency, and
  Docker in the session container let me prove it before pushing.
- **The always-dark stage needs dark content colours.** Writing the contrast test showed the
  UI language's light status colours fail on the dark cabinet (light `--bad` is 2.65:1). Content
  on `[data-stage]` now takes the dark values, and the UI language says so.
- **A workspace package is side-effectful unless it says otherwise.** The shell imports only
  `Kbd`, yet its bundle grew by 27 KB with the commons. `"sideEffects": ["**/*.css"]` in the
  `ui` package brought it back to 223 KB.
- **One schema import brings the whole schema library.** Checking a saved handle with the
  protocol's Zod `handle` put Zod on the first page: the main bundle went from 111 to 148 KB
  gzipped. A Zod-free `isHandle` in `@garbage-day/protocol/handle`, which the schema is now
  built from, brought it back to 112 KB. Client architecture now says the first page loads
  without Zod.
- **A tap shorter than a tick was lost, and no test noticed.** `GD-STORY-001`'s playtest pressed
  arrow keys and I read the result as "moves work", but only rotations and drops (recorded as
  presses) were ever proven; sideways moves were tracked as held keys and a press and release
  inside one 16 ms tick cleared the move before the engine read it. A scripted playtest that
  spread pieces left them all in the middle. Taps are kept for the next tick now, with tests for
  a tap, a tap while holding the other way, and two taps a tick apart. The lesson for playtests:
  check the board, not just that nothing errored.
- **The result card and the drop key collided.** Rematch had focus, Space activates a focused
  button, and Space is hard drop: a player mashing Space as they top out starts the next match
  unseen. The card takes focus now.
- **Soft drop can't follow a finger.** The engine's soft drop is a held speed-up, but the gesture
  table has a slow drag pull the piece down one row per cell. Holding soft drop for a guessed
  number of ticks would drift with the level, so the engine takes `Input.drop`, rows to move down
  at once. It changes no message, so the protocol and the golden replays stand.
- **A scripted flick is slower than a finger.** This sandbox delivers each synthetic touch about
  65 ms after the last, so a scripted flick lifted 50 ms after its final move, which the table
  calls a drag. Real flicks lift while moving; sending the moves and the lift back to back
  reproduced one.
- **The UI language broke its own copy rule.** Its motion table and layout put a "Match DO" badge
  in the centre column, a name the voice rules keep to the developer overlay. It is the Referee
  badge now, true against a local bot and online.
- **The same thing, from the engine.** `GD-STORY-003`'s timing helpers import `TPS`, and the
  engine package said nothing about side effects, so the whole engine joined the first page (112
  → 123 KB gzipped). `engine` and `protocol` now declare `"sideEffects": false` (true of both:
  neither runs anything when loaded), and the first page is 114 KB. Client architecture says
  every package declares its side effects.
- **A stale preview server outlived its build, twice.** My cleanup found the server's PID with
  `ss -ltnp`, which prints nothing in this sandbox, so the gallery's `vite preview` kept port
  4173. The next run's server couldn't bind, and the old one served HTML for the new build's
  scripts. Then `pgrep -f "workerd serve"` matched my own shell, as `pkill -f` did in M1. The fix
  is to keep `$!` from the start and look processes up by exact name (`pgrep -x workerd`).
  It happened a third time in `GD-STORY-007`: a server started with `( … &)` has no `$!` to
  keep, the page it served was from a comparison build of the previous commit, and
  `pgrep -f "[v]ite preview"` still matched my shell, because the same command line started the
  new server. What works: list with `ps`, kill by PID in one command, and start the server in
  another.
- **A skip upstream skipped the production deploy.** `deploy-production` needed only `changes`
  and `garbage-day-ok`, and both succeeded on `main`. But GitHub applies a skip to the whole
  chain below it, and a plain `if:` means `success() && …`. `dependency-review` is skipped on
  every push, so its skip passed through `garbage-day-ok` (which runs under `always()`) to the
  deploy. On pull requests nothing upstream is skipped, which is why the preview never showed it.
- **The contrast tests passed a colour axe failed.** The token tests check every pair in
  `tokens.ts`, and the accent was listed only as a fill and a ring, never as text. The player's
  name is set in it, at 4.35:1 on the light page. Only a scan of the rendered screens finds a use
  nobody listed, so the scan runs on every screen, and the accent's text pairs are now listed.
- **A failed browser test leaves screenshots in the tree.** Vitest's browser mode writes
  `__screenshots__/` beside the test and `.vitest-attachments/` in the package when a test fails,
  and `git status` showed them as new files. Both are now in the project's `.gitignore`.
- **A title test raced its own effect.** The screen-name test checked `document.title` as soon
  as the new screen's heading appeared. The title is set in an effect after the screen paints,
  and on one CI run (the push run of `5b11f4b`; the pull request's run passed) the check came
  first and read `''`. The tests now wait for the title, as a player's tab would.
- **A closed socket kept talking.** After the Match DO closed a flooding socket, the messages
  the client had already sent kept arriving, and each was refused and counted again: 128
  refusals where 20 should have closed it. A DO now ignores any socket it has closed.
- **The client's garbage holes needed the match seed.** `PlayerSim` seeds its hole columns from
  the match seed, and online that seed must never leave the server (US-06): it deals the
  pieces. The Match DO now sends each player a separate hole seed in `start`. `PlayerSim` uses
  its seed for nothing else, so the client can take it as is.
- **A seat-1 player's own Fog would have fallen on them.** The first `ClientMatch` simulated every
  player as seat 0. The referee names a power-up's owner by seat, and the simulation compares
  that with its own index, so a player in seat 1 would have had their own Fog. `start` now says
  the seat (`you`), and the simulation sits there.
- **Opening a socket in a `useState` initializer would have opened two.** StrictMode runs an
  initializer twice in development, so an `OnlineSession` that connected in its constructor
  would have left a discarded second socket that could take the player's seat. The session now
  connects in `start()`, from an effect.
- **Zod reloaded the browser tests.** The match screen's online session brought Zod into the
  browser tests' page. Vite found it mid-run, re-bundled, and reloaded the page under the tests,
  leaving two copies of React ("reading 'useState'"). The browser config now pre-bundles it.
- **Literal colours had crept into the CSS.** The definition of done says colours come from
  tokens, and the token tests check every token. But the overlay's shadow copied the result
  card's `rgb(0 0 0 / 0.4)`, and a search found 17 rules like it across eight files: shadows,
  scrims and tints. Each item checked its own new colours against the tokens, and none of these
  are tokens, so nothing checked them. The search is now an acceptance criterion of
  [`GD-TICKET-025`](../backlog/GD-TICKET-025.md).
- **The app's tests passed against a match that never started.** Once "Play a bot" went through
  the server, 25 of the 26 whole-app tests still passed in happy-dom. No bot match could be made
  there: the request failed and the screen said "Connection lost". They passed because they
  check the screen, not the match. Only the test waiting for a result failed. So the app's tests
  and the accessibility scan now play against `test/fakeServer.ts`, a stand-in for the Worker
  and a Match DO built on the engine's referee. A new test fails if the bot never plays.
