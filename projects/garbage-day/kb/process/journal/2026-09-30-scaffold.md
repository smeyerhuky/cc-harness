## Surprises and what they changed

- **"Latest" and "a day old" collide on release day.** Wrangler 4.144.0 and
  `@cloudflare/vite-plugin` 1.62.2 were published at 21:12 and 21:22 UTC the evening before, and
  `@cloudflare/workers-types` 5.20260930.1 at 01:29 UTC, all under the workspace's
  `minimumReleaseAge` of 1440 minutes. They are not needed until the app shell, so they wait for
  [`GD-TICKET-011`](../backlog/GD-TICKET-011.md). Stack and CI now defines "latest" as the newest
  release at least a day old.
- **`@vitejs/plugin-react` 6 no longer runs Babel.** The React Compiler goes through
  `@rolldown/plugin-babel` (0.2.4) with `@babel/core` 8.0.6 and the plugin's
  `reactCompilerPreset()`. The native oxc route exists but is marked experimental.
- **ESLint's project service needs every linted file inside a tsconfig.** The first lint failed
  with "vitest.config.ts was not found by the project service"; a root `tsconfig.json` that holds
  only the root Vitest config fixed it, and the typecheck now includes it.
- **Knip flagged `react`, `react-dom` and `@types/react` in `ui`** as unused development
  dependencies, although the tests need them; it also reported the entry patterns first written
  in `knip.json` as redundant. `knip.json` is now two lines of ignores.
- **No project references.** Packages export their TypeScript source, so `tsc -b` (which needs
  every package to emit) gave way to `tsc --noEmit -p` per package.
- **The design's path-filtered workflow would have blocked the rest of the repo.** It listed
  eight required checks from a workflow that runs only when the project changes. GitHub waits
  forever for a required check that never starts, so every pull request for another project
  would have hung once the owner marked them required. Pull requests now always start the
  workflow, a `changes` job skips the work when the project is untouched, and one summary check
  is required.
- **A pull request already existed.** The owner had opened #10 from this branch, so the
  acceptance criterion "a pull request shows every job green" was met there, and dependency
  review ran for real instead of being skipped.
- **The proof of concept had a bug and a spec mismatch.** A Bomb landing during the 0.2 s clear
  delay moved the board but not the rows waiting to clear, so the wrong rows cleared; the port
  fixes it. Sudden death stopped at level 15, where the game rules say 20; the port follows the
  rules. Both are in `GD-TICKET-008`'s Resolution; neither needed a new item.
- **The spec uses the name it rules out.** The PRD says the game never uses the Tetris name, but
  the game rules, UI language, controls page and PRD stats call a four-row clear a Tetris. The
  engine now reports clears as data, and choosing the word is
  [`GD-TICKET-018`](../backlog/GD-TICKET-018.md), for the owner (default "Quad").
- **Five of my own test expectations were wrong**, not the engine: two T-spin boards with the
  wrong corners, a wall-kick board that blocked the kick it meant to test, a four-line clear that
  was really a perfect clear, and a gravity count that forgot the spawn tick. Hand-checking and
  the first run caught them.
- **The proof of concept relayed boards during a pause.** The architecture says the referee stops
  relaying while paused, which the proof of concept never did; the port does, and re-sends the
  last locks on resume. Recorded in `GD-TICKET-009`'s Resolution.
- **M1's exit criterion had an uncarried half.** "Identical in Node and the browser" was in no
  item; `009` covers Node. Chromium shares Node's V8, so the real check is Firefox and WebKit:
  [`GD-TICKET-019`](../backlog/GD-TICKET-019.md).
- **Every referee test passed on its first run**, which is suspicious for 24 new tests. Their
  expectations came from the rules text, not from the code's output, and the interruptions
  replay's timeline, read event by event, matched the rules too.
- **The proof of concept loads awkwardly from TypeScript tests.** The project's
  `"type": "module"` makes Node read `live-engine.js` as a module with no exports, so the parity
  test evaluated its source instead.
- **`pnpm/action-setup` points to a newer `pnpm/setup`**, which installs pnpm and Node in one
  step. Kept `pnpm/action-setup` 6.1.0 with `actions/setup-node` 7.0.0, the pair its README still
  supports for pnpm 12, rather than adopting a v1 action in the first CI run.
