# 2026-10-02 — Garbage Day: checking the rematch, and fixing what the check found

**Epic:** [`GD-EPIC-001`](../backlog/GD-EPIC-001.md) · **Milestone:** M3 active · **Branch:** `gd-story-014-rematch-fixes`

## What happened

1. The owner merged pull request #15 and asked what was next. The handoff said
   [`GD-STORY-014`](../backlog/GD-STORY-014.md), but the merge held its feature commit
   (`53736ce`), and the story, the index and the handoff still called it open and next.
2. The owner asked for every acceptance criterion to be confirmed before anything was closed,
   the merged pull request included. The gates passed. Reading the code against the two criteria
   found three gaps: the player who hadn't pressed Rematch was never sent back to the start, a
   bot had no way to answer a rematch, and nobody had played the result in two browsers.
3. The owner confirmed the plan. On a branch off `main`, the server now tells both seats when
   the 30 s lapse (`lapsed`), and the bot asks for a rematch at each result.
4. The first new app test failed: the new match ended at once, `left`. The route keyed the
   match screen on the match counter, so the agreed rematch unmounted the screen that held it.
   The key is gone.
5. The owner asked for the browsers to be installed by the repo's own Playwright. Two players in
   Chromium (a desktop window and a Pixel 7 profile) played a match to its result, pressed
   Rematch, and the second match never showed a result. The wire showed `result` arriving.
   `OnlineSession` had kept its "play began" and "match ended" flags from the first match, so the
   app never heard of the second. The flags are reset on renewal.
6. The three real-browser checks passed (both press; one presses; against a bot). The story was
   closed with a Resolution, and the design, index, roadmap and handoff brought in line.

## Surprises and what they changed

- **Pull request #15's rematch was merged and in production with four faults** that its tests
  and CI did not see: the unpressed player stuck, a bot that never answers, the agreed rematch
  closing its own screen, and the second match never ending on screen. Each test ran one layer.
  The real-browser check found the last two; the app test found the third. A standing rule in the
  handoff now says such a feature is checked through the screen, the session and the server.
- **The first fake-timer test of the Match DO's lapse hung.** The Durable Object's timer isn't
  the test's to fake, so the test waits the 30 s. The worker suite now takes about 37 s.
- **The Playwright installs.** The repo pins 1.63.0; a global `playwright` on the path installed
  other builds, and the tests wanted `chromium_headless_shell-1243` and `firefox-1543`. Installing
  through `pnpm exec playwright install` fixed it. The owner stopped a run of chained install
  commands that looked hung.
- **I said a Durable Object's `setTimeout` could be lost to hibernation.** A pending timer keeps
  the object awake, so that concern is small.
